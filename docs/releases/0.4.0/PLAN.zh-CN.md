# Muse-CI 0.4.0：清晰画布与 SmartDoc 驱动

基线：master `9e87978`（保留远端初始化许可证历史）。分支：`feat/0.4-smartdoc-steps`。

CI 主流程与两个需求见 [CI-RUN.json](CI-RUN.json)。本版本由 Muse-CI 自身管理产品/UI/方案、实现、真实用例与报告，不把文档发布或人工标过作为测试成功。

| 需求 | 功能与交互 | 验收 |
| --- | --- | --- |
| 简洁节点 | 默认卡片只保留标题、状态、运行/重跑、产物和更多；字号扩大，默认 100% 缩放。描述、Skill、工具、材料、日志与人工标过保留在详情/更多。Step 内依赖语义不变。 | 桌面与移动布局；运行门禁、失败、空产物、历史尝试仍可达。 |
| SmartDoc Step | Step 配置入口打开原生配置文档。文档中人可读目标/约束与受限机器配置共同归档。发布校验工具、Skill、材料、节点覆盖后固定原生修订；编辑使消费者过期；活跃 Run 不接受计划变更。 | 无效配置不能生效；未发布/漂移配置阻止运行；Run 留下原生配置快照和摘要。 |
| 智能文档直达 | 文档材料直接进入智能文档，历史文档产物打开固定只读快照；原始数据与下载为次级操作。 | 保留富文本与历史字节，不将旧产物指向可变化的当前文档；错误和权限失败可恢复。 |

实施顺序：统一仓库源码与可复现打包 → Step 配置合同/编译/执行固定 → 简洁卡片与直接文档路由 → 真实 CI 执行测试/报告 → 安装包 Desktop/Mobile 验证 → 细粒度提交与开发分支推送。

兼容：已有流程继续运行，首次配置 Step 时显式建立配置文档；既有 Run、Attempt、产物、文档与人工标过记录不迁移重写。生产市场/OAuth/渠道上架不在本轮功能范围。
